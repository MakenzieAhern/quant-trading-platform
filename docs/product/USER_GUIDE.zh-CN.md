# A 股量化工作台操作指南（v1.2 开发版）

本指南对应本机开发中的产品界面，不代表 v1.2.0 已发布。平台只做本地研究和模拟，不连接真实券商，也不会发送真实资金订单。历史表现不保证未来收益。

## 打开与确认数据

在服务已运行时，用本机浏览器打开 [工作台](http://localhost:5173/)。先看顶部“服务在线”以及旁边独立显示的数据模式和日期；服务在线**不等于**行情是今天的，也不等于来源已审计通过。到[数据中心](http://localhost:5173/data)核对可用数据、日期和来源。需要中文或英文、浅色或深色界面，可在[设置](http://localhost:5173/settings)切换；语言不会改变交易日期或计算结果。

建议一直使用上述 `http://localhost:5173/` 地址，以便找回同一浏览器来源下保存的草稿和未确认请求。`http://127.0.0.1:5173/` 现在也能访问本机 API，但它是**不同的浏览器来源**，不会共享前一地址的本地保存记录；不要为排查未确认的任务或账户创建请求来回切换地址。若页面显示服务不可用，先按上面的 Docker 恢复步骤检查服务，不要修改浏览器安全设置。

## 四种模式不要混用

| 模式 | 可以用来做什么 | 不能说明什么 |
|---|---|---|
| 历史研究 | 用已保存的 A 股数据做个人探索实验 | 已查看的区间不是新的未见样本，也不是未来收益预测 |
| 历史回放 | 让模拟账户逐日走过已存储的交易日 | 不是新到达的实时或日终行情 |
| 合成演示 | 无私有历史数据时学习配置、任务和结果页面 | 虚构价格不是市场证据 |
| 真实新行情前向模拟 | 目标模式：用户启动后接收新完成交易日数据再模拟处理 | **尚未开放**；数据使用权限、当期规则及真实到达验收未通过 |

## 从策略到结果

1. 在[工作台](http://localhost:5173/)选择“开始引导式回测”。若已有草稿，可选择“继续已保存草稿”保留原步骤和请求编号，或选“备份草稿并新建”，先将旧草稿保存为浏览器配置版本，再以新请求编号打开第 1 步；两者都不会自动提交实验。先查看已注册策略的买卖规则、风险和所需数据；不要把策略说明理解成收益推荐。
2. 按四步填写策略、本金与日期/股票范围、成本与风险、最终确认。高级参数按需展开；保存草稿后可回到首页继续。券商佣金及最低佣金是模拟假设，不是已核实报价；在结果页核对实际成本明细。提交前确认数据模式和区间标签。
3. 运行后到[研究列表](http://localhost:5173/experiments)或[任务中心](http://localhost:5173/tasks)找回同一任务。离开页面或刷新不会把已保存的任务变成新任务。只有标为“已完成”的任务才有完整结果；中断、取消和失败记录不展示为成功。
4. 在结果页先看收益、最大回撤、成本、基准和限制，再展开交易、持仓、风控和“为什么订单成交或未成交”。“显示完整精度”只改变展示；日期筛选也不重算完整区间指标。技术原因码可展开核查。

   图表每页最多显示 100 个交易日点位。用“显示基准”切换基准曲线；悬停点位或用“查看指定交易日”选择日期，可读取该日权益、基准和回撤的可用精确值。点“查看该日交易与持仓”会筛到该日并展开交易与持仓；清除日期聚焦可恢复先前区间。打开“图表精确数据”可查看表格，翻页控件可浏览其余点位，均可用键盘操作。切换基准、选日期和翻页只改变展示，不重算上方完整区间指标；缺失值不是零。
5. 从列表选择 2–3 个已完成实验进行比较，并先检查数据版本、区间、本金、成本、风险和策略版本是否一致。页面只核对六项已保存配置，不核实实现指纹、执行模型版本或实际生效费用；认定为受控比较前，还须查看导出报告元数据。模拟调仓预览若存在，必须连同其日期、数据快照和风险拒绝一起阅读；旧结果可能没有预览。结果页可下载带元数据的 JSON 报告和所选记录类型的 CSV 明细；日期筛选只限制导出记录，JSON 汇总指标仍对应完整区间。早期隔离测试曾在真实 Chrome 中收到两种下载事件，但当前版本的文件落盘尚未核验。若报告已准备好但浏览器未自动开始下载，请点击页面的“保存已准备的报告”链接；务必核对浏览器下载记录及实际文件，未确认前视为未保存。若报告准备失败，检查服务状态后再点下载按钮。

### 点击运行后没有收到确认

超时、断连或服务端响应错误不证明任务未创建。先用错误提示中的“查看任务中心”或上面的任务中心链接，按实验名称、配置和创建时间找原任务。若需要返回创建页，恢复原草稿，不修改配置；刷新后须重新勾选确认，再由你点击运行。同配置重试保留同一请求编号，已接受的任务会重新打开；修改配置则使用新的请求编号，可能创建另一个实验。不要为了确认是否成功先改参数再运行。

这与已明确标为失败、取消或中断的任务所提供的“创建或打开关联重试”不同：关联重试是保留原记录的新尝试，不是恢复一条尚未确认的创建请求。

## 查看行情、缓存和更新记录

在[行情与自选](http://localhost:5173/markets)搜索证券，打开证券历史查看日期和来源。原始价格是当日未经复权的价格；研究复权视图用于历史比较，不能直接当成当日可成交价格。加入自选只保存关注列表，不生成订单。顶部按页面标注的数据截至、请求或已观察日期，某条观察值的交易日期，以及服务检查的 UTC 时间是不同概念。

在[数据中心](http://localhost:5173/data)的“原始行情增量请求”中，先查看已有“更新任务历史”，打开任务核对回执、观察值和未解释日期。“刷新”读取已保存状态，不等于重新抓取全部档案。失败记录中的关联重试保留原任务，不能将失败或取消视为已获得完整数据。

当前更新区是**尚未获准用于交易的候选缓存**：即使显示“请求已完成”，也只代表有限供应商请求结束，不代表使用许可、当期证券主表、交易日、ST、规则或公司行动通过验收。新请求需要单独确认来源评估用途；在相关权限和来源门禁解决前，不要将候选观察值用于研究、前向模拟或交易。页面列出的允许日期只是请求边界，不证明当天是交易日或有数据；不会因此重抓整个历史档案。

## 怎样理解结果

- 收益描述该模拟区间的资产变化，不是未来收益承诺。先核对本金、成本及是否为合成数据。
- 最大回撤是资产从此前高点到后来低点的最大跌幅；最终盈利也可能经历较大回撤。
- 胜率只描述盈利交易的比例；少数大亏损可能抵消多数小盈利，胜率不等于收益。
- 基准提供同期比较对象，不是无风险收益；先检查日期和数据模式是否一致。
- 未成交可能来自停牌、涨跌停、现金不足或风控拒绝；先看原因，不要假定信号等于成交。未知值不等于零。

更多解释可直接打开[帮助](http://localhost:5173/help)。

## 模拟账户与中断恢复

到[模拟账户](http://localhost:5173/paper)新建时，表单默认选中明确标记的 2030 合成 A 股演示；旧 AAPL 测试回放仍可明确选择，但不是 A 股数据。仅当数据中心显示已审计历史档案可用时，才能成功创建历史回放。由用户主动启动；可在页面暂停、恢复或停止，并查看现金、持仓、订单、成交和日志。它们不是真实交易。真实新行情前向模式尚不可用，不要把历史补录当作新的市场到达。

在账户详情页的成交记录下方，点击“查看已保存事件”可查看持久化事件日志。每页最多显示 50 条，最新在前；用“更早”“较新”翻页，“刷新”返回最新记录。日志不会自行实时更新，也不会补造已经遗失的记录。

已完成的 A 股历史研究结果页可选择“用这次研究的设置准备独立历史模拟账户”。这只把本金、策略、股票范围、成本和风控参数带到新建表单供核对，不复制研究收益或原来的模拟调仓预览，也不会自动创建账户、启动或提交订单。历史回放每次最多 93 个自然日；若原研究更长，开始日期会留空，必须由你明确选择。新账户有自己的数据快照和流水；仅在条件允许时生成自己的调仓计划。只有确认设置后，才自行创建并启动它。

新建会话后若超时、断连或收到无法确认的错误，先到[模拟账户列表](http://localhost:5173/paper)核对；列表中暂时没有对应会话也不能证明创建失败。在同一浏览器资料和 `http://localhost:5173` 来源下重新打开[新建模拟账户](http://localhost:5173/paper/new)，核对“已保存的模拟账户创建请求”中保存的完整设置，再点击“重试保存的请求”。重试使用首次发送前保存的原请求和请求编号；若服务端已接受，会打开同一个账户。浏览器保存的已确认回执须经当前服务核验后才能打开。保存的创建请求未对清前不能提交不同请求；选择“再创建一个模拟账户”时，也会先核验所有已保存回执，之后才生成新编号并提交。若核验失败，保留原密钥，检查账户列表和数据恢复状态，稍后再核验。若先前结果不明，后来重试又被拒绝，原密钥仍保留供核对，不能因此断定首次创建失败。换浏览器、设备或来源地址，或清除浏览器数据，可能无法读取本地保存的请求；若记录无法读取，先请维护者核对，不要盲目重建。

若研究任务显示“已取消”或“已中断”，打开该任务查看原因；“创建或打开关联重试”沿用原配置，原记录不会被覆盖。重复请求会打开同一关联尝试。

模拟账户断连时，屏幕保留的现金和持仓可能只是最后核验的快照，不是当前余额。连接恢复后先核对会话状态、交易日期和流水，再决定操作；开始、暂停或停止按钮报错也不证明后台未执行。已暂停的账户可在页面提供“继续回放”时由你主动恢复；后端重启不会自动启动它。若会话已标为“已中断”，已有记录只读，不会自动补成交，按页面说明决定是否创建新会话。正常暂停后的进程重启恢复已在隔离历史回放中验证，不等于突然断电、数据库丢失或独立灾备通过。

服务离线、超时或无数据时，先用页面的重试/返回入口；如果仍失败，记下任务链接和屏幕上的技术原因交给维护者，不要清除 PostgreSQL、Redis 或 Docker 卷。

当前开发数据库曾发生恢复事件：两个晚于有效备份的模拟会话（短 ID `4b64380f`、`07d72259`）未能找回，不能把它们当作仍可查询的持久记录。同一物理盘上的备份也不等于独立灾难恢复。在该缺口解决前，不要把此开发版当作可靠的长期账户账本。

## 发布与回退说明

这是未发布的开发版。已发布的稳定基线是 v1.1.0；旧正式研究报告和冻结数据保持只读。当前**没有已验证的 v1.2→v1.1 原位回退**：v1.1.0 不认识当前数据库的新 Alembic 修订，不能对现有卷检出旧 tag 后运行 `make up`。维护者须按[部署与回退门禁](../DEPLOYMENT.md)先用与旧版兼容、独立于当前数据库的升级前备份做隔离恢复演练；当前开发版基线的恢复证明不能替代它。缺少对应备份或演练时，不得声称可以安全降级；也不得覆盖旧 tag、重跑 Official OOS 或删除数据库卷。

现在可以手动打开 Docker Desktop、等待服务就绪，再打开本地平台；这条正常使用与恢复路径不要求你输入终端命令。修正后的 Windows 登录无人自启尚未重新验证，独立物理灾备和真实新手满意度测试也未通过；它们是额外保障，不是本轮新增必需门禁。真正尚未完成的是合法真实新行情前向链路、遗失流水处置，以及完整相关交互、可访问性、视觉、性能和交付验收。因此这仍不是 v1.2.0 正式交付。
